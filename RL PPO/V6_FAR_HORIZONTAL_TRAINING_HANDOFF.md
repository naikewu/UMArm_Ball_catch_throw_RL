## 1. Objective

Train the pneumatic UMArm to:

1. observe a ball launched from a realistic far horizontal location;
2. move the three-finger gripper toward the interception state;
3. match the ball position, direction, and velocity for a soft physical catch;
4. continue moving with the captured momentum instead of stopping;
5. redirect and release the ball toward a fixed far-side target; and
6. minimize contact impulse, excessive force, and mechanical-energy use after
   task success is reliable.

The desired maneuver is one continuous catch-follow-through-throw motion. A
catch, full stop, and separate throw is not the target behavior.

## 2. Implemented Control Hierarchy

The current v6 hierarchy is:

```text
ball, target, arm, pressure, contact, and compliance observation
        -> PPO actor at 30 Hz
        -> tip trajectory, velocity, compliance, and timing intent
        -> inverse kinematics and continuous reference generator
        -> Koopman-MPPI at 150 Hz
        -> 24 pneumatic pressure commands
        -> fitted MuJoCo UMArm at 1 kHz physics/contact integration
```

PPO never directly writes joint angles, joint velocities, or actuator
pressures. Koopman-MPPI remains the only owner of the 24 pressure commands.

Important files:

- `rl_ppo/catch_throw_task.py`: launch, interception, target, and curriculum
  task sampling.
- `rl_ppo/physical_scene.py`: free ball and three-finger gripper MJCF.
- `rl_ppo/catch_throw_plant.py`: MuJoCo stepping, contact wrench, grasp weld,
  release, energy, and variable ball mass.
- `rl_ppo/catch_throw_env.py`: observations, rewards, action masks, curriculum,
  grasp gates, and PPO/MPPI integration.
- `rl_ppo/reference.py`: PPO intent to continuous tip/compliance reference.
- `rl_ppo/networks.py`: actor and critic.
- `rl_ppo/ppo.py`: rollout, GAE, and clipped PPO update.
- `rl_ppo/train_catch_throw.py`: training and deterministic curriculum checks.
- `physical_task_contract.json`: machine-readable physical assumptions.

## 3. Implemented v6 Physical Task

The checkpoint schema is:

```text
umarm_three_finger_far_horizontal_catch_throw_hierarchical_ppo_v6
```

The ball is not launched from underneath the arm. Every curriculum stage uses
a far-side launch from negative world y, with the ball travelling mainly in
positive world y. The target is on the opposite side.

```text
launcher: negative world y
interception: near the home gripper
target offset from home: [0.00, +0.55, 0.00] m
target height: same nominal height as the home gripper
gravity: [0, 0, -9.81] m/s^2
ball radius: 18 mm
nominal ball mass: 25 g
```

The launch sampler chooses a horizontal distance and initial height, then
solves the initial vertical velocity so the free ball reaches the sampled
interception point under gravity:

```text
v0 = (x_intercept - x0 - 0.5 * gravity * T^2) / T
T = horizontal_distance / forward_speed
```

Launch height remains close to the home gripper. Stage 5 varies it only within
plus or minus 30 mm. The gravity-aware entry predictor solves the quadratic
entry-plane crossing and uses piecewise-ballistic swept-sphere checks near the
three fingers.

## 5. PPO Network And Update

Actor and critic are separate multilayer perceptrons.

```text
actor:  81 -> 256 -> Tanh -> 256 -> Tanh -> 10 means
critic: 81 -> 256 -> Tanh -> 256 -> Tanh -> 1 value
```

The actor uses an independent learned Gaussian standard deviation for each
action. Initial `log_std` is `-1.2`; it is clamped to `[-2.5, -0.5]`. Sampled
Gaussian actions are passed through `tanh` to produce bounded actions.

Implemented PPO parameters:

```text
gamma: 0.995
GAE lambda: 0.95
clip ratio: 0.15
value coefficient: 0.5
entropy coefficient: 0.0005
learning rate: 1e-4
epochs per update: 4
minibatch size: 128
gradient norm limit: 0.8
target KL: 0.015
default rollout: 256 policy decisions
```

Advantages are normalized. PPO uses the tanh change-of-variables correction in
the action log probability. Masked action dimensions are excluded from both
log probability and entropy.

The current evidence does not indicate that network width is the main
bottleneck. The actor can change behavior, but current reference timing, action
authority, and reward credit are limiting the useful corrections.

## 7. Physical Grasp And External Force

The gripper consists of one palm and three collision-enabled fingers. The open
end faces the negative-y launcher. Before grasp, the ball is a normal MuJoCo
free body and contact is solved by MuJoCo at 1 kHz.

A grasp is activated only when all four conditions hold during a real contact:

1. MuJoCo reports ball/gripper contact;
2. the ball center is within radial and axial capture bounds;
3. relative speed is below the stage threshold; and
4. ball and gripper velocity alignment is above the stage threshold.

Final Stage 5 thresholds are:

```text
radial limit: 17 mm
axial bounds: [-28, +46] mm
relative speed limit: 0.45 m/s
velocity alignment cosine: 0.75
```

Earlier stages relax these thresholds. Stage 2 uses a 37 mm radial limit, a
0.63 m/s relative-speed limit, and a 0.45 alignment threshold.

On a valid grasp, the code activates a previously disabled MuJoCo weld at the
measured relative pose. It does not teleport the ball or overwrite velocity.
Release disables the weld and preserves free-joint linear and angular velocity.

Contact force is mapped to generalized joint torque with the site Jacobian:

```text
tau_external = J_tip^T * F_contact
```

This torque is supplied to Koopman-MPPI. MuJoCo remains the physical source of
the contact and constraint force.

## 8. Reference And Compliance

Before grasp, the nominal reference blends toward the predicted interception
position and incoming velocity during a velocity-matching window. Current
values are:

```text
velocity matching window: 0.24 s
reference lookahead: 0.12 s
PPO contact velocity adjustment: +/-0.25 m/s before authority scaling
```

After grasp, velocity is continuously blended from captured ball velocity to
the ballistic release velocity:

```text
v_release = (target - release_position - 0.5 * gravity * T_release^2)
            / T_release
```

There is no zero-velocity or settle target between catch and release.

Directional compliance is constructed so the incoming direction can be softer
than transverse directions. A separate force-driven admittance shaper modifies
the tip reference during contact.

## 9. Reward Structure

Before capture, reward includes:

- progress in gravity-aware entry radial error;
- predicted first-contact radial quality;
- near-contact velocity matching;
- `+3` for first physical contact;
- squared penalties for radial, axial, speed, and alignment gate violations;
- `+10` plus radial-quality shaping for valid physical grasp; and
- action-change, contact impulse, and excessive-force penalties.

After capture, reward includes:

- progress in predicted ballistic landing error;
- maintaining forward motion in the incoming momentum direction;
- a penalty for stopping too much during follow-through;
- `+8` for physical release;
- target-entry terminal reward; and
- Stage 4/5 energy penalties.

The energy proxy is:

```text
W_muscle_abs = sum_i integral(abs(F_muscle_i * delta_length_i))
E_proxy = W_muscle_abs + E_finger_close + E_finger_open
```

Assumed finger energies are 0.12 J to close and 0.08 J to open. This is a
mechanical boundary-work proxy, not compressor electrical energy.

## 12. Diagnosis

The far physical geometry is working because the ball contacted the gripper in
100 percent of deterministic episodes. The dominant problem is not failure to
reach the general area. The gripper reaches contact with insufficient velocity
matching and often strikes an outer or axial part of the gripper before a valid
closure state exists.

Current Stage 2B authority is 0.15. Therefore PPO can use at most:

```text
position correction = 25 mm * 0.15 = 3.75 mm per axis
velocity correction = 0.25 m/s * 0.15 = 0.0375 m/s per axis
```

Observed mean radial contact error was 43.8 mm while the Stage 2B gate is 37
mm. The typical required radial correction is already larger than the available
3.75 mm. Mean relative speed was 0.771 m/s while the Stage 2B gate is 0.63 m/s,
a gap of about 0.14 m/s. The available 0.0375 m/s velocity residual is too small.

The 0.24 s velocity-matching window also leaves little time for a pneumatic arm
to accelerate toward a ball travelling about 1.7-1.95 m/s. This is visible as
100 percent speed-failure incidence despite 100 percent physical contact.

The network is not yet the leading suspect:

- the trained policy improved matched-seed capture from 10 to 30 percent;
- deterministic capture improved from 25 to 40 percent between evaluations;
- the actor output is not generally saturated; and
- failures correspond directly to physically insufficient correction authority
  and reference tracking lag.

## 13. Recommended v7 Changes, Not Yet Implemented

Do not start the 100000-step full run before these changes and a new validation.

### 13.1 Start Velocity Matching Earlier

Change `ReferenceConfig.velocity_match_window_s` from `0.24` to `0.40` seconds.
Run a small ablation over `0.35`, `0.40`, and `0.45` seconds if time permits.

Log the desired and actual gripper velocity at first contact. The comparison
must separate reference-planning error from MPPI tracking error.

### 13.2 Increase Useful Stage 2 Authority

Recommended first candidate:

```text
Stage 1:       0.05, unchanged
Stage 2A/B/C:  0.20 / 0.35 / 0.50
Stage 3:       0.65
Stage 4:       0.85
Stage 5:       1.00
```

Increase `ReferenceConfig.contact_velocity_adjustment_mps` from `0.25` to
`0.45 m/s`. Keep the 25 mm base interception-offset limit initially.

With Stage 2B authority 0.35, PPO would have:

```text
maximum position correction: 8.75 mm per axis
maximum velocity correction: 0.1575 m/s per axis
```

These values match the observed error scale much better.

### 13.3 Improve Pre-Capture Reward Credit

Current near-contact velocity terms are small compared with terminal grasp and
truncation rewards. Add or strengthen geometry-gated dense terms for:

```text
delta relative-speed improvement
parallel relative velocity
transverse relative velocity
velocity-alignment improvement
entry radial improvement
```

Apply kinematic gate penalties to each pre-capture contact window, not only the
first physical contact. Keep them bounded to avoid one impact dominating an
entire rollout.

Do not weaken physical grasp gates to manufacture success. Improve the approach
state instead.

### 13.4 Separate Contact Diagnostics

Log three different event records:

```text
first physical contact metrics
best compatible pre-grasp contact metrics
actual grasp-event metrics
```

Current episode-level failure booleans remain true after an early bad contact,
even when a later contact succeeds. Separate records will make reward tuning
and soft-catch evaluation clearer.

### 13.5 Strengthen Curriculum Gates

Capture rate alone is insufficient. A recommended Stage 2B promotion gate is:

```text
deterministic capture rate >= 80 percent
mean grasp-event relative speed <= 0.50 m/s
mean grasp-event alignment >= 0.65
mean grasp-event radial offset <= 25 mm
unsafe-force rate = 0
```

These should use grasp-event metrics, not any-contact metrics.

### 13.6 Save The Best Checkpoint

Continue saving `ppo_latest.pt`, but also save `ppo_best.pt` whenever the
deterministic evaluation improves. Rank checkpoints lexicographically by:

```text
capture/release/target success
then lower grasp relative speed
then lower radial error
then lower impulse and energy
```

### 13.7 Validate Before Full Training

After implementing v7:

1. run all tests and the physical smoke test;
2. compare zero-action and untrained-policy baselines;
3. run fixed Stage 2A briefly;
4. run a fixed Stage 2B validation for at least 5000 steps;
5. require the strengthened deterministic gate; and
6. only then start the automatic 100000-step five-stage run.

Because action scaling, reward semantics, and reference timing will change,
create a v7 checkpoint schema and a new output directory. Preserve v6 and do
not resume its optimizer state.

# V26 数字孪生终局规划与分阶段 PPO 改进方案

## 1. 当前结论

V25 的工程链路有效，但候选策略没有达到可部署水平。第四阶段的 200 个新场景中，V15 接住 171 次、命中 168 次；V25 候选释放 116 次、命中 107 次。安全、命中且配对效用高于 V15 的场景只有 34/171（19.88%）。场景隔离的 gate 验证集上只有 6/34（17.65%）属于这个区域，因此 gate 只能选择始终回退 V15。

失败不是 PPO 是否 on-policy 的问题。V25 的 PPO rollout 是 on-policy；主要问题在 PPO 之前的控制与信息结构：

1. 数字孪生只在预览采集时用于分支打分，策略和 gate 执行时没有真正比较多个未来。
2. 分支只预测 2 秒，并且只施加一个动作，后续全部保持不变；实际释放常在接球后约 6–7 秒发生。
3. gate 只读取交接瞬间的 39 维当前状态，没有候选未来的可释放性、预计释放时间、预计落点和风险。
4. 候选只控制力缩放和半径缩放。必须先证明这两个自由度足以让大多数场景进入释放区域，才能继续训练 PPO。
5. 当前稀疏终局奖励把“进入释放区域”和“释放后落点精度”混在一起。V25 已经学到较好的条件命中率，但没有先解决释放可达性。

V26 的原则是：先做可达性证明，再做模仿学习，再做严格 on-policy PPO，最后才做 V15/候选接管判断。任何前置门槛失败都停止后续长训练。

## 2. V26 控制结构

V15 继续冻结并负责接近、接球和默认安全轨迹。V26 只在已经持球的连续交接点以后工作。

每个决策点执行以下过程：

1. 从当前状态建立可复现的数字孪生快照。
2. 对所有有效动作分别预测到释放或释放窗口结束，而不是固定预测 2 秒。
3. 每个动作输出以下未来特征：
   - 是否能在窗口内释放；
   - 未来最小校准落点误差；
   - 到达最小误差与预计释放的时间；
   - 预计落点 `dx/dy`；
   - 最大关节角、夹持破坏和 OOD 风险；
   - 相对 V15 的预测效用差。
4. Actor 根据当前可测状态和每个动作的未来特征选择动作。
5. 150 Hz 校准释放器继续拥有最终开爪权，Actor 不能直接释放。
6. 最终监督器只有在候选的鲁棒预测优于 V15 时接管，否则执行完整 V15 回退。

数字孪生训练教师可使用完整快照。供最终部署使用的 Actor 只能读取传感器派生状态和明确记录的未来预测，不能读取场景种子、真实隐藏球状态或最终结果。若以后连接真实机械臂，需要增加“测量状态到数字孪生状态”的同步适配器；当前 `TwinSnapshot` 只能克隆正在运行的仿真环境，不能直接证明真实系统上的孪生初始化正确。

## 3. 先做动作空间可达性审计

在训练任何新网络之前，用至少 200 个全新、与 V25 所有训练/验证/gate 种子隔离的场景执行三组配对结果：

1. 冻结 V15 基线；
2. 9 个固定力/半径组合分别运行到终局，记录每个场景的 oracle 最佳结果。

这一步只回答“现有力/半径动作空间是否包含可达解”。直接在200个场景的每个0.5秒决策上评估9条终局分支计算量过大，已由5场景smoke验证不适合作为第一道门槛。逐决策的终局MPC改到后续`collect`阶段，只在策略实际访问的状态上生成监督标签。

进入下一阶段的最低条件：

- 接球数必须与 V15 相同；
- 静态终局 oracle 的接球后释放率至少 90%；
- 释放后的 15 cm 命中率至少 90%；
- 无夹持破坏，最大关节角不超过 36 度；
- 至少 25% 的已接球场景相对 V15 有安全正收益。

如果静态终局 oracle 仍达不到 90% 释放率，说明问题属于动作空间，不训练 PPO。先做受控消融，按顺序增加 `spinup_s` 和 `radial_damping` 的小范围动作；只有数字孪生 oracle 证明它们提高可达性且通过原有安全/OOD 检查，才加入 Actor。不得用放宽释放误差或修改开爪条件掩盖不可达问题。若新参数超出原释放校准的数据覆盖，还必须重做相应的释放校准验证。

## 4. 奖励与课程学习

V26 将候选训练拆成两个课程，避免命中精度掩盖不可释放问题。

### 4.1 Reachability 课程

主目标是进入合法释放区域。终局优先级固定为：不安全最差；未释放其次；安全释放优于任何未释放结果。数字孪生未来势函数采用：

`Phi = release_probability + exp(-predicted_min_error / scale) - time_penalty - risk_penalty`

动态 shaping 使用 `gamma * Phi(next) - Phi(current)`，并限制整回合 shaping 的幅度，使它不可能抵消“释放/未释放”的终局顺序。动作变化和反向切换只保留很小的正则项。

Reachability 课程只有在固定的 100 场景验证集上连续三次满足以下条件才结束：接球后释放率不低于 90%，安全约束通过。

### 4.2 Accuracy/efficiency 课程

从 Reachability 合格 checkpoint 开始，保持释放率硬约束，然后优化：

- 15 cm 命中；
- 落点误差；
- 接球到释放时间；
- 动作变化和平滑性。

这一阶段才使用与 V15 的配对效用差作为主要终局改进信号。若任一验证轮释放率跌破 Reachability 门槛，checkpoint 不得晋级。

接球冲击、速度匹配、压力和能耗不在 V26 的同一个 Actor 中训练。V15 的接球部分仍冻结。待抛球链路稳定后，再建立独立的高速接球柔顺 Actor，以相对接触速度、冲击峰值/冲量、压力积分和真实气动能耗模型为目标，并用接球率作为硬约束。

## 5. 网络与 PPO

V26 不再把所有未来特征简单拼成一个大向量。模型使用共享的逐动作编码器：

- 当前状态编码器处理 39 维可测上下文和时间/历史状态；
- 同一个小型 action encoder 分别处理 9 个动作的未来特征；
- action scorer 为每个有效动作生成 logit；
- reachability head 预测每个动作的释放概率、最小误差、预计释放时间和风险；
- critic 将当前状态与动作集合聚合后估值。

这种结构对 9 个动作共享参数，样本效率高于把 9 组特征全部平铺。网络规模控制在约 1–2 万参数。Reachability 与 quality 使用分开的 value head，避免二值可达性和连续质量回报互相污染。

PPO 初始设置保留已经验证稳定的 V25 量级：actor LR `1e-4`、critic LR `3e-4`、clip `0.1`、4 epochs、minibatch 256、`gamma=0.995`、`lambda=0.95`。结构和奖励修复前不再通过提高学习率解决问题。每批 rollout 只消费一次；每次更新后丢弃，因此正式 PPO 仍为 on-policy。建议每批 64 回合、每 5 次更新验证一次、至少 20 次更新、早停耐心从 2 提高到 4；最终更新数由验证结果决定，不预先承诺跑满。

## 6. 数据计划

现有数据的用途如下：

- V15 checkpoint：直接复用并冻结；
- 原 1200 回合数据：只复用其交接上下文和 9 个初始力/半径动作标签，作为初始 Actor 的辅助预训练；
- V25 的 940 条预览决策：可作为单步辅助标签和回归测试，不能作为 V26 终局 MPC 的主要监督数据；
- V25 第三、第四阶段结果：作为失败样本与诊断基线，不作为 V26 gate 的合格训练集；
- V23 释放校准：动作范围不变时继续复用；若增加超出覆盖的新控制量，则重新验证或重新拟合。

V26 必须重新收集终局分支数据，因为旧预览没有“预测到释放/窗口结束”的特征。建议先做 200 场景 oracle 审计；通过后按 DAgger 方式收集至少 1000 个成功接球上下文：先收集约 300 个 MPC 专家回合，预训练后再用当前策略访问到的状态补充三轮数据，直到累计已接球上下文不少于 1000。这样能覆盖策略真实访问的失败状态，而不只是静态随机状态。

预训练/DAgger 数据可以离线重复使用；进入 PPO 后，每个 rollout 必须由当次策略新采集并只更新一次。

## 7. 需要新增或修改的程序

V25 结果必须保留，V26 使用新 schema 和新输出目录，避免旧 checkpoint 被新逻辑误读。

### 新增

- `teacher_rl/twin_terminal_planner.py`：终局分支、鲁棒多分支预测、V15 配对预测和动作可达性特征。
- `teacher_rl/twin_reachability_env.py`：V26 环境、未来特征观察、动作 mask 和安全边界。
- `teacher_rl/twin_reachability_model.py`：共享逐动作编码器、reachability/quality heads 和双 critic。
- `teacher_rl/twin_mpc_gate.py`：基于未来预测的保守接管规则；学习模型只校正孪生预测误差，不独立决定接管。
- `teacher_rl/twin_mpc_ppo.py`：oracle、collect、pretrain、pilot、reach-train、quality-train、gate、screen、evaluate 子命令。
- `tests/test_twin_mpc_v26.py`：终局 horizon、快照恢复、无未来泄漏、势函数、on-policy 单次消费、零接管和回退测试。
- `START_V26_TWIN_MPC_PPO.ps1`：逐阶段入口、路径固定、resume 和产物检查。

### 复用且原则上不修改

- `teacher_rl/twin_snapshot.py`：继续使用已通过逐位恢复验证的快照；V26 仍需重新执行验证。
- V15 checkpoint 与 V15 接近/接球源码。
- V23 释放校准器及 150 Hz 释放保护。
- V25 源码和 `teacher_runs/v25_twin_residual` 全部保留为实验记录。

### 文档

- 新增 V26 运行指南；
- 在 `RL_PPO_SYSTEM_TRAINING_MASTER_SUMMARY.md` 中记录每个门槛和实际结果；
- 每个产物保存 schema、源码、V15、校准器、数据集和上游 checkpoint 的 SHA-256。

## 8. 实施完成后的运行顺序

以下是计划中的顺序；在 `START_V26_TWIN_MPC_PPO.ps1` 实际创建并通过 smoke test 以前，不应在终端运行这些命令。

1. `verify`：验证快照、终局分支、传感器输入和无信息泄漏。
2. `oracle`：200 个新场景做动作空间可达性审计。失败则修改动作空间并只重跑 `verify -> oracle`。
3. `collect`：收集终局 MPC 专家数据，累计至少 1000 个已接球上下文。
4. `pretrain`：用旧 1200 初始动作数据和新终局 MPC 数据训练 Actor/reachability heads。
5. `pilot`：100 个独立场景测试预训练候选。未达到至少 80% 释放率时返回 `collect/pretrain`，不启动 PPO。
6. `reach-train`：强制候选的 reachability on-policy PPO。
7. `quality-train`：从合格 reachability checkpoint 优化命中、时间和平滑性。
8. `gate`：至少 1000 个新的配对接球上下文校准未来预测与接管边界。
9. `screen`：200 个固定开发场景，检查非零接管、总体性能不低于 V15、配对收益和安全。
10. `evaluate`：screen 通过后，运行一次 200 场景独立盲测。

依赖关系不是“一整段全部运行”。每一步完成后先检查产物和门槛，再运行下一步。失败只重跑受代码或数据变化影响的阶段：

- 只修改 gate 阈值/校准：重跑 `gate -> screen -> evaluate`；
- 修改 Actor、奖励或 PPO：重跑 `pretrain/pilot`（若 checkpoint schema 变化）以及两个 PPO 阶段、gate、screen、evaluate；
- 修改动作空间、环境动力学、终局分支或释放特征：从 `verify -> oracle` 开始全部重跑；
- 只增加同 schema 的 DAgger 数据：重跑 `pretrain` 及其后阶段；
- V15 或释放校准器改变：全部重跑。

## 9. 最终验收标准

候选单独合格：

- 接球率与 V15 相同；
- 接球后释放率不低于 90%；
- 释放后 15 cm 命中率不低于 90%；
- 无夹持破坏，最大关节角不超过 36 度；
- 至少 25% 场景安全优于 V15。

混合系统合格：

- 接管率至少 20%，避免“永远 V15”的真空通过；
- 总体接球、释放、命中均不低于同场景 V15；
- 平均落点误差不劣于 V15 超过 5 mm；
- 接管场景的平均配对效用差大于 0，置信下界不小于 0；
- 在共同成功场景中，平均接球到释放时间至少缩短 10%；
- 所有安全、连续交接、停顿和关节检查通过；
- 最差参数分箱有足够样本且命中率不低于预先写入合同的下限。

这套流程不能预先保证某个网络一定达到目标，但能保证在昂贵 PPO 之前发现动作空间是否根本不可达，并保证最终所谓“成功”来自独立场景上的非零改进，而不是降低阈值或始终回退 V15。

# V18：BC基础控制 + 在线PPO抛球与释放探索

## 这一版做什么

继续使用冻结的V15 BC、已有PID/逆动力学及气动执行器模型，但不再只让PPO微调接球参数。
PPO每轮用当前策略驱动MuJoCo，收集新轨迹，再更新策略。这是on-policy在线仿真训练，不需要先重新采集teacher数据。
它不是从零直接学习24路压力，也没有解冻BC网络。V15/V16/V17代码和模型不覆盖。

默认 `throw` 阶段首先学习：在保持接球控制不变的条件下，调整甩动驱动力、轨道半径和释放时机，尝试改善连续抛球精度及耗时。
**此阶段不能指望改善发生在抓住之前的相对速度或最初撞击峰值。** 接球柔顺性需要后续 `catch` / `joint` 实验，且必须在独立场景中验证。

## 新增控制权限

| 控制项 | 默认范围/规则 |
|---|---|
| 抛球切向驱动力 | 相对自适应名义值 +/-1 N；绝对限制7-14 N |
| 轨道目标半径 | 相对自适应名义值 +/-0.02 m；绝对限制0.50-0.74 m |
| 释放请求 | 动作大于+0.75时请求释放，小于-0.75时暂缓，否则由弹道预测器决定 |
| 最早策略请求 | 接球切入轨道控制后0.5 s；不等于0.5 s时强制扔球 |
| 中性释放 | 保留预测误差不超过4 cm、至少甩动2.5 s的规则，并加传感器和关节条件 |
| 接球到甩动 | 不调用先刹停/等待的流程，沿用连续接管，压力混合0.20 s、轨道加速2 s |
| 最终压力指令 | 沿用1-30 psi限制 |

策略释放仍须持球、测量有效、满足速度/仰角条件且当前测量关节偏转不超过36度。
策略可越过原来的4 cm预测误差门槛，但不能越过这些状态条件；具体阀门时刻仍由当前控制周期内的预测候选确定。
默认噪声下较高释放阈值用于减少训练初期随机丢球，并不保证初期成功率不下降。

可选的 `catch` / `joint` 阶段接球权限：共同压力残差+/-0.5 psi，速度匹配系数+/-0.02，Kp为0.90-1.05倍、Kd为0.95-1.10倍，Ki不变。
接球后0.30 s缓冲期可调共同压力及Kd，后0.10 s平滑退出；缓冲Kd沿用0.8-1.3倍范围。
滤波时间常数0.05 s，压力残差变化率限制20 psi/s。默认 `throw` 下上述接球/缓冲动作均不学习。

以前观测到的约0.025 psi是实际平均修正量，不是权限上限。本版重点开放对抛球真正有作用的控制项，而不是单纯扩大气压。

## 网络和训练参数

- 10维残差动作，分阶段掩码；第5维混合时间禁用。默认只开放抛球的3维动作。
- Actor输入114维，Critic输入145维；特权仿真状态仅进Critic，不进入Actor。
- Actor/Critic各2层256单元SiLU。Actor复用BC前两层的已有输入权重，新增输入初始权重及输出层为零；BC本身冻结。
- Actor学习率 `1e-4`，Critic `3e-4`；PPO clip `0.1`，KL阈值 `0.02`，每轮3个epoch，batch 256。
- gamma `0.997`，GAE lambda `0.995`，entropy系数 `0.001`，梯度范数限制1。
- 默认10轮，每轮16条新训练轨迹，共160条；20条固定验证场景，每5轮验证。
- 额外先跑20条BC、20条V18零残差基线。因此默认训练命令总计240条仿真轨迹，不是只运行160条。
- 训练、验证及最终评估种子分开；保存来源指纹和场景清单，防止把训练场景当作独立评估。

奖励保留抓住/释放/命中与落点误差，扣除初始约束力峰值、冲量、相对速度、接触冲量、缓冲载荷、低速停顿；新增关节超限、45度中止和持球时间成本。
这些是多目标权衡，不保证所有指标会一起进步。仿真weld约束力不能直接称为实物接触力。

## 启动命令

从项目根目录，在PowerShell中执行：

```powershell
& '.\RL PPO\START_V18_RL.ps1' -Mode Explore
```

这就是当前建议先运行的有界在线探索训练，不再要求V17的 `selected_config.json`。
上限为50轮，每轮5-32条；这些限制只约束计算预算，并不是实机安全保证。
运行结束后做40条新场景、BC/V18零残差/最新训练策略三组配对评估，共120条轨迹：

```powershell
& '.\RL PPO\START_V18_RL.ps1' -Mode Evaluate -Checkpoint Latest
```

中途正常中断后，从最后完整更新恢复，重跑尚未完成的那一轮：

```powershell
& '.\RL PPO\START_V18_RL.ps1' -Mode Resume
```

只查询磁盘中的完成情况、检查点轮次、来源一致性及评估是否结束，不启动仿真：

```powershell
& '.\RL PPO\START_V18_RL.ps1' -Mode Status
```

`Status`不检测操作系统进程；它检查保存的训练状态，不能把`resumable`单独解释为“进程已停止”。
`-Checkpoint Candidate`（Evaluate的默认值）评估选模候选；`Latest`评估最后完整训练轮次；`Accepted`要求质量验收模型确实存在。
当前160条训练的best为第0轮，因此默认Candidate只是零残差基线，启动器会提示。查看训练后的RL请明确指定Latest。
三种模型评估使用不同输出目录，避免覆盖；已用于一种独立评估的种子不能在另一新目录重复使用。
同一模型、同一目录与参数可以重复执行，已完成组直接读缓存。不要根据独立评估反复选模或调参后继续把同组场景称为最终测试集。

自定义过参数时，恢复必须重复同一套Stage、预算、种子和目录；不能用Resume改变总训练轮数。
只有先生成 `ppo_latest.pt` 后才能恢复。首次基线尚未完成就中断时，应使用新目录与新种子重开。

## 输出与判断

默认目录：`teacher_runs/v18_online/explore_throw/`。

- `run_config.json`：完整参数、来源指纹、验证场景及种子。
- `update_*.json`：随机探索训练统计、有效动作样本数、PPO梯度和KL。
- `validation_*.json`：确定性策略的配对验证、控制记录及保护门槛。
- `ppo_latest.pt`：最新完整更新，用于恢复。
- `ppo_candidate.pt`：按中止次数、命中/抓取/释放及精度排序的研究候选，可能仍是第0轮零残差，不代表通过质量验收。
- `ppo_accepted.pt`：仅在至少80条验证场景且满足成功率、关节/连续性等保护，以及相对V18零残差初始峰值与冲量均改善至少3%时生成。它仍不是独立最终评估认证。
- `evaluation_latest_40/comparison.json`：最新训练模型的新场景比较；Candidate的默认路径仍为`evaluation_40/comparison.json`。

默认只有20条验证场景，因此不会生成 `ppo_accepted.pt`，这是有意的。没有accepted文件不等于没训练。
比较应优先看确定性评估，不把随机探索中的命中率直接当最终策略成功率。

V18零动作也新增了释放保护，因此不能假设它与V17零动作轨迹相同。每次新实验都重新计算V18基线。
关节达到45度时记录中止并在下一个控制边界结束回合；它不是机械硬限位，也不能保证积分过程中绝不超过45度。候选验收仍要求整条轨迹最大偏转不超过36度。

先完成默认抛球实验，再决定是否启动 `-Stage joint`。改变Stage必须另开目录和种子；当前入口会从冻结BC+零残差重新初始化，不支持把throw权重直接作为joint续训。
无需现在继续大批采集teacher，也不要把这版称为“已经优于BC”。本版先检验扩大有效权限后，在线PPO是否能学出有价值的改进。

本次代码测试和短仿真结果见 [V18_IMPLEMENTATION_RESULTS.md](V18_IMPLEMENTATION_RESULTS.md)。
